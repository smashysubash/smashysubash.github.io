## The problem

Each client ran on its own deployment: a core service, a login service and a blockchain service. Every new client meant more infrastructure, more databases and more cost, even for clients who only used a small part of the platform.

## What I built

One NestJS service that serves every tenant. Each tenant keeps its own isolated database, and the app resolves the tenant on every request and routes to the right connection. I chose a database per tenant over a shared schema for clean data separation.

- One app for both REST and GraphQL.
- The login service folded into the core, and the blockchain service dropped.
- Legacy data moved with idempotent migration scripts, so a rerun never duplicates anything.

## Fixes along the way

- **Atomic scan flow.** The old flow created a linked record in a second, separate call that sometimes never fired, leaving orphans. Now both records are created in one atomic step.
- **Login lockout.** Brute-force protection the old system never had.
- **Race-free counters.** Batch numbers come from an atomic sequence instead of an unindexed counter.
- **Pagination at scale.** Checked the pagination pipeline at 200k records and added the index it was missing.

## Result

10+ tenants live in production on one service.
